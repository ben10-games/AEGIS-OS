# ADR-0006: Build in a pinned container; pin every input

Status: Accepted
Date: 2026-11-13

## Context

Builds must give the same result in CI and on a developer machine, and must not silently pick up new upstream content.

## Decision

All image work runs inside a builder container pinned by digest. The base image is pinned by digest and mirrored. RPMs come from a generated lockfile with checksums. CI actions are pinned by commit SHA; Python lint tools are installed with `--require-hashes`. The task runner is GNU Make.

## Consequences

- Deviation from the approved blueprint: the blueprint named `just`. Make is already present in Claude Cloud, on CI runners and in Fedora, so it removes one tool that would itself need pinning.
- Input updates arrive only as reviewed commits. The bump job (`update-inputs`
  workflow) produces a candidate lock and diff; it never writes to the repository.

### RPM lock as implemented (P1-15, 2026-11-20)

- `image/packages/rpms.in.yaml` names what each install step adds;
  `image/packages/rpms.lock.yaml` records every resolved package (name, epoch, version,
  release, arch, size, SHA-256, source repository and path) plus the base digest and the
  SHA-256 of `rpms.in.yaml`, so a changed input or base makes the lock stale and the
  static tests fail.
- **Deviation:** the lock is generated by `scripts/bump-inputs` with dnf on the pinned
  base image, not by `rpm-lockfile-prototype`. That tool is not packaged in Fedora;
  installing it would add an unpinned dependency to the supply chain it is meant to
  pin. The format is an AEGIS one (one line per package, strict parser in
  `scripts/rpmlock.py`, standard library only).
- **Transport:** the blueprint's fallback is used from the start: the locked RPMs are
  published once as an immutable image `ghcr.io/ben10-games/aegis-os/rpm-inputs`
  (tag = hash of the package list, never overwritten) and builds pull it by digest.
  Fedora's `updates` repository keeps only the newest build of each package, so a lock
  pointing at mirrors breaks within days (the same reason the base image is mirrored,
  BUG-7). The repository path is still recorded for provenance. Assumption A4
  (updates-archive) is therefore not needed and not tested.
- Builds run with `--network=none` and every repository disabled; RPMs are checked
  before use for size, SHA-256, header identity and a valid signature by Fedora's
  release key from the base image (`scripts/fetch-inputs`), and again by checksum
  inside the build (`image/build/install-locked`). There is no fallback source.

## Verification

S-03, R-01, R-02; negative input tests in `scripts/test-inputs` and
`tests/static/test_rpm_lock.py`.
