# GUI v2: performance, VirtualBox display integration, Liquid Glass 2.0

Branch `claude/aegis-os-gui-v2` (from the Live ISO branch). Owner request: the desktop
lags in VirtualBox, looks basic, and does not resize to full screen. User guide:
`VIRTUALBOX_GUIDE.md` sections 3a and 8; release notes: `CHANGELOG-GUI-v2.md`.

## Phase A: what makes the desktop slow

Measured in CI (QEMU/KVM on a GitHub runner, VirtualBox-like hardware, 2 CPUs, 4 GiB;
`tests/vm/test_live_iso.py`, run 45604938784). Real VirtualBox was not available.

| Question | Finding |
|---|---|
| Hardware or software rendering? | Software. KWin reports `Compositing Type: OpenGL ES`, renderer `llvmpipe (LLVM 23.1.5, 256 bits)`, Mesa 26.2.7. The VM has no render node (`/dev/dri` holds only `card0`). VirtualBox without 3D acceleration is in the same situation: VMSVGA without 3D gives no GPU. |
| VMware SVGA / vmwgfx | In QEMU, `vmwgfx` refuses QEMU's old SVGA v2 device ("Hardware has no pitchlock", probe error -38) and the desktop runs on simpledrm (Live ISO run 45204188680). In VirtualBox, `vmwgfx` drives VMSVGA (the owner's boots worked); not measurable here. |
| Cost of the glass | Frame meter animating under the launcher popup (KWin must re-blur changing content every frame): KWin used 111 % (Balanced) and 116 % (Full) of one CPU, against 37 % with Performance Glass (no blur); frame rate 58–59 fps in all three. Without anything blurred over the animation: 32–34 % in every profile. On a runner CPU the cost shows as CPU time; on a slower host or with fewer cores it becomes dropped frames (lag). |
| Frame pacing | Frame meter (Qt Quick frames, 10 s): 59–60 fps, median 17 ms, 95th percentile 17–20 ms, 0–5 frames over 33 ms per 10 s in every profile once warmed up. The first measurement after login was worse (49.9 fps, 48 frames over 33 ms in run 45601312768): startup work competes. |
| CPUs | 4 CPUs: 59.8 fps, KWin 45 % of one CPU for the same animation (llvmpipe spreads work over all CPUs). |
| Idle | After login, desktop shown: KWin 1.9 %, plasmashell 0.1 % of one CPU; 1.3 GB of memory used. |
| Wayland vs X11 | Plasma 6.8 has no X11 session, so there is nothing to compare or fall back to; KWin's Wayland compositor is the only path. |
| RAM overlay vs disk | The live root is a SquashFS read from the CD plus a RAM overlay. Reads of not-yet-cached files come from the (virtual) CD; writes go to RAM, which is faster than any disk. The overlay is not a rendering bottleneck; it competes for memory (Chrome: 2.6 GB). Persistence is a separate milestone. |

Conclusion: the lag comes from software rendering of the blur and animations, not from
the GPU driver, the RAM overlay or idle load.

## Phase B/C: what was changed

- **Rendering profiles** (`image/rootfs-gui/usr/libexec/aegis/glass-profile`): Full,
  Balanced, Performance, Automatic; at login (`/etc/xdg/autostart/aegis-glass-profile.desktop`)
  the automatic choice reads KWin's renderer and picks Performance Glass for llvmpipe /
  softpipe / swrast and Balanced Glass otherwise. Settings go to the user's own
  `kwinrc` and `kdeglobals` (blur on/off and strength, magic lamp / squash / scale
  effects, `AnimationDurationFactor`); KWin reloads them at once. No profile needs
  administrator rights. User interface: AEGIS Appearance (`org.aegisos.appearance`,
  pinned in the dock).
- **Baloo** file indexing off by default (`/etc/xdg/baloofilerc`).
- **VirtualBox guest tools** in the Live ISO (`virtualbox-guest-additions` 7.2.22, locked
  step `live-apps`): `vboxservice.service` (enabled, `ConditionVirtualization=oracle`) and
  `vboxclient.service`; VBoxDRMClient passes the host's window size to `vmwgfx`, and KWin
  follows the output's new preferred mode. Under QEMU both units are skipped by their
  condition (tested). The live 1920x1080 login helper now exits inside VirtualBox.
- **Measurement**: AEGIS Frame Meter (`org.aegisos.framemeter`, Qt Quick `FrameAnimation`
  ticks over 10 s after a 3 s warm-up, result as an `AEGIS-FRAMES` line at warning level)
  and `/usr/libexec/aegis/graphics-report [--measure]`.

Not done, and why:

- No QPainter (non-OpenGL) KWin backend and no software Qt Quick scene graph: both would
  need a session restart per change and were not measured; the profile change already
  removes the measured cost.
- No GPU-accelerated refraction shader: there is no GPU in the target configuration
  (VirtualBox without 3D), and on llvmpipe such a shader would cost more than the blur
  that was measured above.

## Phase D: Liquid Glass 2.0 (AEGIS Glass)

- Plasma theme `aegis-glass`, generated by `scripts/make_plasma_theme.py` (committed
  output, a static test checks that it regenerates identically). Frames for the panel,
  dialogs (popups, notifications, OSDs), tooltips and widgets: corner radius 18 / 14 / 10
  / 14 px; tint from the colour scheme (class `ColorScheme-Background`, so AEGIS Dark and
  AEGIS Light both work); light-facing 1 px top edge and arcs, faint side outline, dark
  bottom edge, white top sheen, gradient shadows; `mask-` pieces define the blur region.
  `translucent/` variants (tint 58–80 %) are used while KWin's blur is available, the base
  files (tint 90–95 %) otherwise. Task manager: glass hover and focus highlights, a
  running-app underline, accent underline for the active app.
- Colour schemes AEGIS Dark (existing) and AEGIS Light (new); `accentColorFromWallpaper`.
- Breeze decorations without borders, large soft shadows, centred titles (`/etc/xdg/breezerc`,
  look-and-feel defaults).
- Dock: floating, centred, fit to content, `dodgewindows`, 3.4 grid units high.
  Launcher: Kickoff (the Application Dashboard is not part of this Plasma build: CI run
  45601312768).
- What it is not: no optical refraction, no per-pixel lighting; the highlights are drawn
  into the theme. Translucent Dolphin sidebars are not possible with the Breeze style.

## Phase E: tests

`tests/vm/test_live_iso.py` (offline, 2 CPUs): UEFI boot, Plasma session, renderer and
automatic profile, switching all three profiles (blur loaded or not, animation factor)
with frame meter and CPU shares with and without a glass popup, launcher click and
search, resolution changes (1366x768, the largest offered mode, 1920x1080) with the dock
centred at the bottom and no black corner, VirtualBox units present and skipped, idle CPU
and memory, plus all earlier Live ISO checks (security dashboard, SELinux, admin password,
network, audio, clean power-off). `tests/vm/test_live_flatpak.py` (network, 4 CPUs):
frame meter with 4 CPUs, Flathub, Chrome install and start. `tests/vm/test_gui.py` (the
sealed QCOW2 GUI image): Full Liquid Glass loads KWin's blur.
